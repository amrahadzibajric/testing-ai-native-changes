### Proposed import format (delivery team proposal — pending client confirmation)

One **CSV file** (UTF-8, comma-separated, header row), exported from the spreadsheet by Office Operations:

| Column | Example | Rule |
|--------|---------|------|
| `room` | Team | Must match an active room name exactly |
| `person_email` | jane.doe@company.com | Must match a person already added by an admin |
| `date` | 2026-10-05 | `YYYY-MM-DD`, within the import week, Mon–Fri |
| `start` | 09:00 | `HH:MM`, 15-minute grid, ≥ 08:00 |
| `end` | 10:30 | `HH:MM`, 15-minute grid, ≤ 20:00, 30 min–4 h after start |
| `attendees` | 4 | Whole number, 1 to room capacity |

- People are added in the tool **before** the import, so every booking links to a real user. Email is the key because it will match the future Microsoft sign-in.
- The import runs every booking rule: no overlap, office hours, duration, capacity and the 3-booking limit. Rows that break a rule are **rejected and listed in a report** for the admin to fix and re-import. Nothing is silently changed.
- Office Operations is assumed to own the spreadsheet clean-up (for example resolving known double-bookings) before export.

## Working assumptions carried forward (not contradicted by client)

- Single office, single time zone.
- Web app for desktop and phone browsers.
- Availability view shows a room as busy without revealing who booked it.
- "Upcoming" = confirmed bookings that have not started.
- No-show, room release, and done marking happen automatically.
- The booker checks in (attendees are a head count only).
- Admins follow the same time rules as employees; only the 3-booking limit is waived for admins booking for themselves.
- Rooms taken out of use can be reactivated.
- Lowering room capacity leaves existing bookings unchanged.
- No public-holiday calendar in the pilot.
- A rebooked no-show remainder still follows the 30-minute minimum (e.g. no 10:45–11:00 booking).
- Greenfield build; the spreadsheet is retired after the one-week import.
