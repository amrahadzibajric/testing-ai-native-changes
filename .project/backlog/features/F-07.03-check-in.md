## Description

Lets the booking owner check in from their own laptop or phone from 10 minutes before the start to 15 minutes after. Only the owner can check in; admins cannot check in on someone's behalf.

## Scope Detail

- Check-in service for the owner within the window
- Refusals: too early, too late (no-show), not the owner, not Confirmed
- Phone-first check-in control on My bookings
- Audit BookingCheckedIn

## Technical Approach

Lifecycle service comparing the office clock instant with start minus 10 minutes and start plus 15 minutes; uses the shared effective-status definition so check-in and no-show never disagree.

## Stories

---

### S-07.03.01: Check in within the window

**Estimated Hours:** TBD

As a Software Engineer, I want the owner to check in from 10 minutes before to 15 minutes after the start so that a booking is confirmed as used.

_Acceptance criteria:_

- [ ] For a Confirmed booking starting 14:00, check-in at 13:50 and at 14:14 succeeds and the status becomes Checked in with the check-in time recorded.
- [ ] The window boundaries use one shared definition with the no-show rule, so no moment is both check-in-eligible and no-show.
- [ ] A checked-in booking then behaves as started (it cannot be edited or cancelled).

_Notes:_ LC-07; E2E-005 steps 1 and 2.

---

### S-07.03.02: Refuse check-in outside the rules

**Estimated Hours:** TBD

As a Software Engineer, I want clear refusals so that a user knows why they cannot check in.

_Acceptance criteria:_

- [ ] Check-in at 13:45 for a 14:00 booking is refused with the time when check-in opens (13:50).
- [ ] Check-in after the window (for example 14:16), when the booking is already a No-show, is refused with a message that the booking was released.
- [ ] Check-in by a person who is not the booking owner, including an admin, is refused; a booking that is not Confirmed cannot be checked in.

_Notes:_ ADR-0015 decision 4; E2E-005 failure paths, E2E-006 failure path.

---

### S-07.03.03: Build the phone-first check-in interaction

**Estimated Hours:** TBD

As a Software Engineer, I want a large, obvious check-in control on the phone so that people can check in when they arrive.

_Acceptance criteria:_

- [ ] When the window is open, the booking on My bookings shows a Check in control with a touch target of at least 44 px; when not open it explains when it opens.
- [ ] Success shows the Checked in status without leaving the page.
- [ ] The same control works on desktop and meets the accessibility baseline.

_Notes:_ S02-my-bookings-mobile; ADR-0003 (own device); NFR-016.

---

### S-07.03.04: Audit check-in

**Estimated Hours:** TBD

As a Software Engineer, I want check-ins audited so that the record shows who checked in and when.

_Acceptance criteria:_

- [ ] BookingCheckedIn records the acting person and the time from the office clock.
- [ ] The audit event is written in the same transaction as the status change.
- [ ] A refused check-in writes no audit event.

_Notes:_ NFR-020.
