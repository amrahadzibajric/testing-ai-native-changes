## Description

Gives Office Operations a clear template and worked example for the CSV export and asks for an anonymised sample so that the import is built against real patterns. This is the integration readiness step recommended by the CSV integration assessment.

## Scope Detail

- CSV template header row and a worked example document
- Guidance on exact room names, email keys, date and time formats and the import window
- Request for an anonymised export and the plan for using it as a fixture

## Technical Approach

Short documents produced by the delivery team from ADR-0011 and the integration assessment. No code.

## Stories

---

### S-01.03.01: Produce the CSV template and worked example

**Estimated Hours:** TBD

As a Program Architect, I want a CSV template and a worked example so that Office Operations knows exactly how to prepare the export.

_Acceptance criteria:_

- [ ] The template shows the header `room,person_email,date,start,end,attendees` and each column rule from ADR-0011 (exact active room name, existing person email, `YYYY-MM-DD` within the window on Monday to Friday, `HH:MM` on the 15-minute grid, attendees as whole number within capacity).
- [ ] The example shows a few valid rows and explains the 5-working-day window, the 3-booking limit per person and that rejected rows are returned in a report, never silently changed.
- [ ] The document states that people and rooms must exist before import and that the file is UTF-8, comma-separated, with a header row.

_Notes:_ Marked "pending client confirmation" until ADR-0011 is confirmed.

---

### S-01.03.02: Request an anonymised export and plan its use as a fixture

**Estimated Hours:** TBD

As a Program Architect, I want to request an anonymised spreadsheet export from Office Operations so that real-world rejection patterns are known early.

_Acceptance criteria:_

- [ ] A written request is prepared for Office Operations asking for an export with names and emails replaced by fictional values.
- [ ] The plan states that a real export is anonymised before it enters the repository and that, if none arrives, the synthetic sample from F-09.06 is the only fixture.
- [ ] The response (or absence of one) is recorded as an open item for the demonstration.

_Notes:_ Supports security finding SEC-14: no real personal data enters the POC.
