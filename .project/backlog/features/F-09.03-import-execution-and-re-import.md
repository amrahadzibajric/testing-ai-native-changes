## Description

Writes accepted rows as Confirmed bookings through the booking-write service, detects exact duplicates on re-import, records the ImportRun with consistent counts and an audit event, and meets the import timing target.

## Scope Detail

- Rows written through the write service with source Import and the import run id
- Duplicate detection: same room, owner, start and end among non-cancelled bookings
- ImportRun counts and invariants; ImportRunCompleted audit
- Concurrency and performance targets

## Technical Approach

Each accepted row uses a short write transaction on the shared write path; a duplicate lookup precedes creation; counts are computed from the outcome list.

## Stories

---

### S-09.03.01: Write accepted rows as Confirmed bookings

**Estimated Hours:** TBD

As a Software Engineer, I want accepted rows written as ordinary bookings so that imported bookings follow the lifecycle like any other.

_Acceptance criteria:_

- [ ] Each accepted row becomes a Confirmed booking with source Import and the import run id, owned by the matched person and created by the importing admin.
- [ ] Rows go through the booking-write service, so overlap and the 3-booking limit hold even if someone books manually during the import.
- [ ] Imported bookings appear in My bookings, availability and the admin list like manual bookings.

_Notes:_ IM-03, IM-08; E2E-013 step 3.

---

### S-09.03.02: Detect duplicates on re-import

**Estimated Hours:** TBD

As a Software Engineer, I want identical rows reported as duplicates so that re-importing a corrected file does not create bookings twice.

_Acceptance criteria:_

- [ ] A row with the same room, owner, start and end as an existing non-cancelled booking is reported as Duplicate with the existing booking id and is not created.
- [ ] Re-importing a file whose valid rows were already imported creates no new bookings.
- [ ] A row matching only a cancelled booking is treated as new.

_Notes:_ IM-09; E2E-013 step 4.

---

### S-09.03.03: Record the import run and its counts

**Estimated Hours:** TBD

As a Software Engineer, I want each run recorded with consistent counts so that every row is accounted for.

_Acceptance criteria:_

- [ ] The ImportRun stores who ran it, the times, file name and size, outcome Completed, and counts where total equals imported plus duplicate plus rejected.
- [ ] ImportRunCompleted is audited with the counts and no email addresses.
- [ ] Several runs (corrected re-imports) are expected and each is recorded separately.

_Notes:_ data-model import.md; NFR-020.

---

### S-09.03.04: Meet the performance and concurrency targets

**Estimated Hours:** TBD

As a Software Engineer, I want the import to finish quickly and safely so that admins can import in one interaction.

_Acceptance criteria:_

- [ ] A file of 300 and of 500 rows completes, including the report, in under 60 seconds locally.
- [ ] Long imports do not block the sweeper or other users beyond the busy timeout because each row uses a short transaction.
- [ ] A booking made manually while the import runs is never overlapped by an imported row.

_Notes:_ NFR-004, NFR-005; arch v1.2 Import Flow.
