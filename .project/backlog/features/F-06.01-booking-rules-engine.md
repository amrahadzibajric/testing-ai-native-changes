## Description

Implements the stateless rule set every booking path relies on: time grid, duration, office hours, no past, capacity, overlap and the 3-booking limit, each returning a named result so that users and the import report see the same reason text.

## Scope Detail

- Time rules: 15-minute grid, 30 minutes to 4 hours, 08:00 to 20:00 Monday to Friday, no past booking
- Capacity rules: attendees at least 1 and not above room capacity; inactive rooms refused
- Overlap: active bookings block, back-to-back allowed, no-show occupies only until the no-show moment
- Limit: 3 upcoming per employee, admin for self unlimited, on-behalf counts, edits do not count
- Named refusal results shared with the import report

## Technical Approach

A pure rules component with no I/O, taking the request, the room, current data facts and the office clock, returning a list of named failures. All rules evaluate in office local time.

## Stories

---

### S-06.01.01: Implement the time rules

**Estimated Hours:** TBD

As a Software Engineer, I want the grid, duration, office-hours and past rules so that every booking fits how the office works.

_Acceptance criteria:_

- [ ] Start and end must be on :00, :15, :30 or :45; duration must be 30 minutes to 4 hours inclusive.
- [ ] The whole booking must lie within 08:00 to 20:00 office local time on Monday to Friday; a Saturday, Sunday, 07:45 start or 20:15 end is refused.
- [ ] A booking starting before the current minute is refused; admins follow the same time rules as employees.

_Notes:_ BR-01 to BR-05, BR-11, BR-14, BR-15; E2E-001 failure paths.

---

### S-06.01.02: Implement capacity and room-state rules

**Estimated Hours:** TBD

As a Software Engineer, I want the capacity and room-state rules so that a room is never booked for more people than it fits or when it is out of use.

_Acceptance criteria:_

- [ ] Attendees must be a whole number of at least 1 and at most the room's capacity at the time of booking or edit.
- [ ] A booking against an inactive room is refused.
- [ ] Lowering a room's capacity later does not affect the rule for bookings already made, only for new and edited bookings.

_Notes:_ BR-07, BR-13; RM-05.

---

### S-06.01.03: Implement the overlap rule

**Estimated Hours:** TBD

As a Software Engineer, I want the overlap rule so that a room is never booked twice for the same time while back-to-back meetings remain allowed.

_Acceptance criteria:_

- [ ] A booking that overlaps an active booking (Confirmed, Checked in or Done) in the same room is refused; one ending at 10:00 and one starting at 10:00 are both accepted.
- [ ] Cancelled bookings block nothing; a No-show booking occupies the room only until its no-show moment.
- [ ] When evaluating an edit, the booking's own current slot is excluded from the check, and stored status may lag the clock (effective status is used).

_Notes:_ BR-06; E2E-002; ADR-0008; effective status per ADR-0018.

---

### S-06.01.04: Implement the booking-limit rule

**Estimated Hours:** TBD

As a Software Engineer, I want the 3-upcoming-booking limit so that employees cannot hold rooms "just in case".

_Acceptance criteria:_

- [ ] "Upcoming" counts only the person's Confirmed bookings that have not started; a fourth is refused with a message naming the limit.
- [ ] A booking made by an admin for another person counts toward that person's 3; an admin booking for themselves has no limit.
- [ ] An edit never increases the count; bookings already in the tool count when an import runs.

_Notes:_ BR-08 to BR-10; LC-04; ADR-0014 rule 2; E2E-003, E2E-004.

---

### S-06.01.05: Return named, consistent refusal results

**Estimated Hours:** TBD

As a Software Engineer, I want each rule to return a named result so that every refusal tells the user which rule was broken and the import report can reuse the same names.

_Acceptance criteria:_

- [ ] Every failure carries a stable rule code and a readable message that names the rule (for example "Maximum booking length is 4 hours").
- [ ] The rule codes are the same names used by the import report (OffGrid, OutsideOfficeHours, DurationTooShort, DurationTooLong, CapacityExceeded, InvalidAttendees, Overlap, LimitExceeded, InPast, RoomInactive).
- [ ] The manual flow reports the first failure; the import flow can collect every failed rule for a row.

_Notes:_ NFR-017; data-model import.md rule codes.
