## Description

Produces the report that lets Office Operations fix rejected rows: each rejected or duplicate row with its line number, the values as supplied and every broken rule by name, plus a downloadable CSV of the rejected rows. Cell values are escaped against spreadsheet formula injection, and report rows are purged once the admin settles the import.

## Scope Detail

- Report rows for rejected and duplicate rows with raw values and all reasons
- Downloadable rejected-rows CSV suitable for correction and re-import
- Escaping of `=`, `+`, `-`, `@` leading cells in HTML and CSV
- Settle action that purges report rows while keeping run counts and the audit event

## Technical Approach

ImportReportRow persistence per run, generated download from those rows, a single escaping function used by view and export, and a purge command that deletes only ImportReportRow.

## Stories

---

### S-09.04.01: Store and show the report rows

**Estimated Hours:** TBD

As a Software Engineer, I want every rejected and duplicate row reported with its details so that nothing is lost or silently changed.

_Acceptance criteria:_

- [ ] Each rejected row is stored with line number, the six raw values as supplied and every broken rule by name with a readable message; each duplicate row references the existing booking.
- [ ] Values are stored exactly as received; nothing is corrected or trimmed.
- [ ] The report is available only to admins.

_Notes:_ IM-06; data-model ImportReportRow.

---

### S-09.04.02: Provide a downloadable rejected-rows CSV

**Estimated Hours:** TBD

As a Software Engineer, I want to download the rejected rows as a CSV so that Office Operations can correct and re-import them.

_Acceptance criteria:_

- [ ] The download contains the rejected rows in the six-column import format plus a trailing `reasons` column, with the original values.
- [ ] Re-uploading a corrected file that still contains the trailing `reasons` column is accepted; the column is ignored.
- [ ] The download is available only until the import is settled.

_Notes:_ E2E-013 step 4; extension of ADR-0011 to flag.

---

### S-09.04.03: Escape formula injection in the report and download

**Estimated Hours:** TBD

As a Software Engineer, I want cells that start with `=`, `+`, `-` or `@` neutralised so that opening the report or the CSV in a spreadsheet cannot execute a formula.

_Acceptance criteria:_

- [ ] Such cell values are escaped in the HTML report and in the downloadable CSV; the visible content still shows the original text.
- [ ] Values are validated against strict patterns before being echoed.
- [ ] The sample CSV contains a formula-leading cell that proves the escaping.

_Notes:_ SEC-06 (Medium); CWE-1236.

---

### S-09.04.04: Settle the import and purge the report rows

**Estimated Hours:** TBD

As a Software Engineer, I want an explicit settle action so that report rows containing emails that match no person do not stay in the database.

_Acceptance criteria:_

- [ ] An admin can settle an import run after confirmation; all ImportReportRow rows for the run are deleted, and the download is no longer available.
- [ ] The ImportRun summary counts and the audit event remain.
- [ ] A run that has not been settled keeps its report so that corrections can be made.

_Notes:_ Accepted by the project lead 2026-09-29 (ADR-0024); refines NFR-021 for this one table; the trigger is a working assumption.
