# F-06.05: Rebook Freed No-show Remainder

**Feature ID:** F-06.05
**EPIC:** [E-06: Room Booking and Availability](../epics/E-06-room-booking-and-availability.md)
**Status:** Planned
**Phase:** Phase 1 — POC
**Sprint Range:** TBD (Phase 10)
**PD Estimate:** TBD (Phase 9)
**Last Updated:** 2026-09-29
**Status Reason:** Baseline WBS v1.0. M-01 capability 5. Built on ADR-0013 (Proposed); pending client confirmation.
**Surfaces:** Web, Phone browser
**Dependencies:** F-06.01, F-06.03, F-07.04 (no-show and effective status)
**ADR References:** ADR-0008, ADR-0013 (Proposed)
**Integration points:** None
**Open questions / risks:** The 30-minute minimum on remainders is Proposed and unconfirmed; if reversed, a 15-minute remainder becomes bookable and only the duration rule for remainders changes (E2E-006 failure path 11:15 to 11:30). *(Sources: ADR-0013; client-qa-2026-09-29.md, Working assumptions)*

## Description

Once a booking is a no-show, the time from the no-show moment to the original end becomes bookable again, with start times on the 15-minute grid, so an unused room is released for others.

## Scope Detail

- Remainder becomes free from the no-show moment; it is not a separate entity
- New booking start on the 15-minute grid, at or after the no-show moment and not in the past
- 30-minute minimum applied to the remainder (pending ADR-0013)
- Timeline and phone list show the remainder as free; the original booker's late check-in is refused

## Technical Approach

No new storage: the overlap rule already treats a no-show as occupying only until its no-show moment; this feature verifies and surfaces that behaviour end to end.

## Stories

---

### S-06.05.01: Make the freed remainder bookable

**Estimated Hours:** TBD

As a Software Engineer, I want the time after a no-show moment to be bookable so that an unused room is released to others straight away.

_Acceptance criteria:_

- [ ] After a booking is a no-show (stored or effective), another user can book the same room from a grid start at or after the no-show moment up to the original end.
- [ ] A start that is off the 15-minute grid (for example 10:20) is refused with the named rule.
- [ ] The time before the no-show moment still blocks the room, and no link to the original booking is stored.

_Notes:_ ADR-0008; E2E-006 steps 1 to 3.

---

### S-06.05.02: Apply the 30-minute minimum to the remainder [pending ADR-0013]

**Estimated Hours:** TBD

As a Software Engineer, I want the general 30-minute minimum to apply to a rebooked remainder so that there is one consistent duration rule.

_Acceptance criteria:_

- [ ] Start 10:45 and end 11:15 (30 minutes) is accepted; 11:15 to 11:30 (15 minutes) is refused with the duration rule.
- [ ] The behaviour comes from the ordinary duration rule with no special case, so reversing ADR-0013 changes one place only.
- [ ] The feature notes and the demonstration pack mark this rule as pending client confirmation.

_Notes:_ Working assumption from client-qa-2026-09-29.md, not contradicted by the client.

---

### S-06.05.03: Show the remainder and refuse a late check-in

**Estimated Hours:** TBD

As a Software Engineer, I want the freed time shown as free and the original booker's late check-in refused so that the release is visible and unambiguous.

_Acceptance criteria:_

- [ ] The timeline board and phone list show the remainder as free from the first valid grid start.
- [ ] The original booker attempting to check in after the no-show is refused with a message that the booking was released.
- [ ] The rebooked remainder appears as a normal booking in the new owner's My bookings.

_Notes:_ E2E-006 failure paths; UI on F-06.03 components.
