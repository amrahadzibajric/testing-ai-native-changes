## Description

Writes the instructions anyone on the delivery team needs to run, reset and safely present the POC on a developer machine.

## Scope Detail

- Prerequisites, run, first-start behaviour, reset
- Explicit prohibitions: LAN binding, machine IP binding, public tunnels; not for real bookings
- Configuration reference and troubleshooting

## Technical Approach

A single markdown run guide in the repository root or docs folder; commands verified on a clean machine.

## Stories

---

### S-11.01.01: Write the run and reset instructions

**Estimated Hours:** TBD

As a Program Architect, I want clear run and reset instructions so that any team member can start the POC and return it to a clean state.

_Acceptance criteria:_

- [ ] The guide lists prerequisites (the .NET SDK; browsers for E2E), the `dotnet run` command and the localhost URL.
- [ ] It explains first-start behaviour: file creation, migrations, bootstrap admin and seed data.
- [ ] It explains reset (delete the database file and restart) and how to run the test suites.

_Notes:_ Verified by following the guide on a clean machine.

---

### S-11.01.02: State the safeguards

**Estimated Hours:** TBD

As a Program Architect, I want the security safeguards stated plainly so that the unauthenticated POC is never exposed.

_Acceptance criteria:_

- [ ] The guide forbids binding to all interfaces or a machine IP and forbids public tunnels and any other remote sharing of the running app; screen sharing of the browser is the way to show it to the client.
- [ ] It states that the POC uses synthetic data only and is not for real bookings or real personal data.
- [ ] It explains that phone behaviour is shown with a narrow browser window or device emulation.

_Notes:_ SEC-13, SEC-14; ADR-0024 Option C rejected.

---

### S-11.01.03: Provide the configuration reference and troubleshooting

**Estimated Hours:** TBD

As a Program Architect, I want a configuration reference and troubleshooting list so that common failures are quick to fix.

_Acceptance criteria:_

- [ ] Every configuration setting (BootstrapAdmin, OfficeTimeZone, Seed, Import switches and caps, database and key ring locations) is listed with its purpose and default.
- [ ] Troubleshooting covers missing bootstrap settings, port already in use, time zone data missing and a locked or corrupted SQLite file.
- [ ] Error messages quoted in the guide match the messages the application produces.

_Notes:_ Startup failure messages come from F-02.01 and F-02.05.
