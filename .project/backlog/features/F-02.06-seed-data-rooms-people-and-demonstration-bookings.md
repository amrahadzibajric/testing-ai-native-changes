## Description

Seeds the reference data the POC starts with: exactly the specification's four rooms, a set of obviously fictional people, and sample bookings that make each demonstration scenario possible. All data is synthetic.

## Scope Detail

- Rooms exactly as specified: Focus 2, Team 6, Board 12 active; Old Room 4 inactive; no others
- Synthetic people: at least one admin, several employees, one inactive; fictional names, non-routable emails
- Sample bookings across the coming days covering the demonstration scenarios
- Controls: toggle, idempotence, separation from the bootstrap and from migrations

## Technical Approach

A startup seeder invoked after migration and bootstrap. Sample bookings are computed relative to the start time and placed only in valid office slots.

## Stories

---

### S-02.06.01: Seed the rooms exactly as specified

**Estimated Hours:** TBD

As a Software Engineer, I want the four rooms seeded exactly as in the specification so that the demonstration matches the client's reality.

_Acceptance criteria:_

- [ ] After a fresh start, Focus (2), Team (6) and Board (12) are active and Old Room (4) is inactive, and no other room exists.
- [ ] Restarting does not duplicate or alter rooms that already exist.
- [ ] Room names are matched case-insensitively for idempotence.

_Notes:_ Source: room-booking-spec.md, Rooms we have today; ADR-0024 decision 3.

---

### S-02.06.02: Seed synthetic people

**Estimated Hours:** TBD

As a Software Engineer, I want synthetic people with at least one admin and several employees so that both roles can be demonstrated without real data.

_Acceptance criteria:_

- [ ] At least one admin and several employees are created (the design uses 8 active people and 1 inactive), with obviously fictional names and non-routable email addresses.
- [ ] One inactive person exists so the picker's "active only" rule can be shown.
- [ ] No real person, real company address or real client data appears anywhere in the seed.

_Notes:_ SEC-14; NFR-013. Separate from the bootstrap admin.

---

### S-02.06.03: Seed sample bookings that make each scenario demonstrable

**Estimated Hours:** TBD

As a Software Engineer, I want sample bookings dated relative to the start time so that a free slot, a busy room, a check-in, a person at the 3-booking limit, a late cancellation for review, a no-show and an admin-cancelled booking can all be shown.

_Acceptance criteria:_

- [ ] Sample bookings cover: a free slot and a busy room, a booking about to start for check-in, a person at the 3-booking limit, a late cancellation flagged for review, a no-show, a Done booking and a booking cancelled by admin.
- [ ] Every seeded booking obeys the booking rules (grid, duration, office hours, weekday, capacity, no overlap).
- [ ] When the application starts outside office hours or on a weekend, scenarios that need "today" are placed on the next working day and the startup log states which scenarios are available now.

_Notes:_ There is no demonstration clock control; the presenter uses these bookings or waits (ADR-0024).

---

### S-02.06.04: Control and separate the seed

**Estimated Hours:** TBD

As a Software Engineer, I want the demonstration seed switchable and separate from schema and bootstrap so that the application can start without demo data.

_Acceptance criteria:_

- [ ] A configuration setting turns demonstration seeding on or off; with it off, only migrations and the bootstrap step run.
- [ ] Seeding is idempotent and safe to run on every start.
- [ ] Deleting the database file and restarting restores the seeded state.

_Notes:_ The run instructions (F-11.01) state that the POC is not for real bookings.
