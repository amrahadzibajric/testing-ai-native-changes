## Description

One service that cancels all future Confirmed bookings of a deactivated room or person as "cancelled by admin", records who did it, never late-flags them, and reports the count beforehand so admins see the consequence.

## Scope Detail

- Cascade for room or person: future Confirmed, not started bookings only
- Cancellation origins RoomDeactivated and PersonDeactivated, cancelled by the acting admin, never late-flagged
- Preview count for the warning
- Owner-visible "Cancelled by admin" label
- Atomic with the deactivation and audited

## Technical Approach

A lifecycle service method used inside the deactivation transaction of the room and people services; one audit event for the deactivation plus one per cancelled booking.

## Stories

---

### S-07.05.01: Cancel future bookings for a deactivated room or person

**Estimated Hours:** TBD

As a Software Engineer, I want a shared cascade so that room and person deactivation release their future bookings consistently.

_Acceptance criteria:_

- [ ] All Confirmed bookings that have not started for the room (or owner) are cancelled with origin RoomDeactivated (or PersonDeactivated), cancelled by the acting admin, and never late-flagged.
- [ ] Bookings that are in progress, Checked in, Done, No-show or already Cancelled are untouched.
- [ ] The cancelled bookings free their rooms and reduce affected people's upcoming counts.

_Notes:_ E2E-010 steps 1 and 2, E2E-012 steps 1 and 2.

---

### S-07.05.02: Provide the preview count

**Estimated Hours:** TBD

As a Software Engineer, I want a count of bookings that would be cancelled so that admins are warned before confirming.

_Acceptance criteria:_

- [ ] The preview returns the number of future Confirmed bookings that a room or person deactivation would cancel, using the same selection as the cascade.
- [ ] The count is correct at the moment of confirmation (recomputed inside the transaction, with a message if it changed).
- [ ] The preview changes nothing.

_Notes:_ RM-07, PI-06.

---

### S-07.05.03: Make cancelled-by-admin visible to the booker

**Estimated Hours:** TBD

As a Software Engineer, I want the affected booker to see that an admin cancelled the booking so that they know it was not their action.

_Acceptance criteria:_

- [ ] A booking cancelled through the cascade shows the label "Cancelled by admin" in My bookings and in admin lists.
- [ ] Such bookings never appear in late-cancellation views or counts.
- [ ] The label is derived from the cancellation origin and is not a separate stored status.

_Notes:_ LC-12, AO-05; data-model decision accepted 2026-09-29.

---

### S-07.05.04: Keep the cascade atomic and audited

**Estimated Hours:** TBD

As a Software Engineer, I want the cascade to succeed or fail as one unit so that a partial cancellation cannot occur.

_Acceptance criteria:_

- [ ] Room or person state change, all cancellations and their audit events are committed in one transaction; a failure rolls everything back.
- [ ] One audit event per cancelled booking carries the origin, plus one for the deactivation itself.
- [ ] A cascade over 50 bookings completes within the normal request time.

_Notes:_ NFR-020; ADR-0025 write serialisation.
