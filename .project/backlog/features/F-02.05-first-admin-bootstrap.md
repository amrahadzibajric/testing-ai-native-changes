## Description

Because there is no login and admins are created by admins, an admin must exist at startup. This feature seeds one from configuration when no active admin exists, safely and idempotently, and fails clearly when it cannot.

## Scope Detail

- Bootstrap step on every startup
- Idempotence: no change when an active admin exists
- Fail-fast when no admin exists and configuration is missing or invalid
- Audited as a system action; ordinary person record afterwards

## Technical Approach

A startup step, separate from the demo seeder, reading the `BootstrapAdmin` settings section and using the person creation path with actor System.

## Stories

---

### S-02.05.01: Create the configured admin when none exists

**Estimated Hours:** TBD

As a Software Engineer, I want a startup step that creates the admin from configuration when no active admin exists so that the application is always usable.

_Acceptance criteria:_

- [ ] With no active admin and valid `BootstrapAdmin` settings, one active person with role Admin is created on startup.
- [ ] With an active admin already present, the step changes nothing and never overwrites, re-promotes or reactivates anyone; running it repeatedly is safe.
- [ ] The email is treated as an ordinary unique, case-insensitive person key.

_Notes:_ Separate from the demonstration sample people (F-02.06).

---

### S-02.05.02: Fail clearly when no admin can be established

**Estimated Hours:** TBD

As a Software Engineer, I want startup to fail with a clear message when no admin exists and the configuration is missing or invalid so that the application never runs without an admin or with a hard-coded account.

_Acceptance criteria:_

- [ ] With no admin and missing or invalid settings, startup stops with a message naming the missing setting.
- [ ] No default account name or email exists anywhere in the code.
- [ ] With an active admin already present, missing settings do not stop startup.

_Notes:_ Production-safe behaviour required by ADR-0024.

---

### S-02.05.03: Audit the bootstrap and keep the admin ordinary

**Estimated Hours:** TBD

As a Software Engineer, I want the bootstrap recorded as a system action so that the origin of the first admin is traceable.

_Acceptance criteria:_

- [ ] Creation records a PersonCreated audit event with actor kind System.
- [ ] The bootstrap admin can later be edited, deactivated or demoted through people management once another active admin exists (last-admin protection PI-07 still applies).
- [ ] The step logs a single line stating that an admin was created or that one already existed, without the email address.

_Notes:_ SEC-09; PI-07.
