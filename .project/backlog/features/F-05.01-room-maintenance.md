## Description

Lets admins add rooms, rename them, change capacity and see the room list with name, capacity and state.

## Scope Detail

- Add a room with name (1 to 100 characters, unique ignoring case) and capacity (whole number of at least 1)
- Rename and change capacity; lowering capacity leaves existing bookings unchanged
- Room list with active or inactive state
- Web and phone screens

## Technical Approach

Room service in the M-03 module with audit events RoomCreated and RoomUpdated; screens built on F-03 components.

## Stories

---

### S-05.01.01: Add a room

**Estimated Hours:** TBD

As a Software Engineer, I want an admin add-room form so that a new room becomes bookable without a code change.

_Acceptance criteria:_

- [ ] An admin can add a room with a name and a capacity of at least 1; it is active and appears in availability.
- [ ] A name that already exists, ignoring case, or a capacity below 1 is refused with a message naming the rule.
- [ ] RoomCreated is audited.

_Notes:_ RM-01, RM-02; E2E-011 step 1.

---

### S-05.01.02: Rename a room and change its capacity

**Estimated Hours:** TBD

As a Software Engineer, I want to rename a room and change its capacity so that the room list stays accurate.

_Acceptance criteria:_

- [ ] An admin can rename a room (still unique ignoring case) and change its capacity.
- [ ] Lowering capacity leaves existing bookings unchanged; a new booking or an edit of an existing booking must respect the new capacity.
- [ ] RoomUpdated is audited with the old and new values.

_Notes:_ RM-05; E2E-011 steps 2 to 4.

---

### S-05.01.03: Show the room list

**Estimated Hours:** TBD

As a Software Engineer, I want an admin room list showing name, capacity and active state so that admins see the current state of every room.

_Acceptance criteria:_

- [ ] The list shows every room including inactive ones, with name, capacity and a clear active or inactive marker.
- [ ] Only admins can open the list; employees see only active rooms through the booking screens.
- [ ] The seeded rooms appear exactly as specified after a fresh start.

_Notes:_ RM-01; NFR-010.

---

### S-05.01.04: Build the room screens for web and phone

**Estimated Hours:** TBD

As a Software Engineer, I want the room screens from the design so that admins can maintain rooms on desktop and phone.

_Acceptance criteria:_

- [ ] The web screen is table-first with a detail pane; the phone screen is a list with a detail view, following S03-rooms and S03-rooms-mobile.
- [ ] Add and edit forms show validation messages for duplicate name and invalid capacity.
- [ ] The screens meet the accessibility baseline.

_Notes:_ Design direction: admin views are table-first.
