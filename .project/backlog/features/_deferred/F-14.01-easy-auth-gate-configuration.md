## Description

Places the tenant-only Easy Auth gate in front of production and test as code, requires authentication on every path except a health probe, restricts to assigned pilot users, secures the other App Service endpoints and adds an automated reachability check.

## Scope Detail

- Single-tenant app registration and consent by client IT; user assignment required for the pilot users
- Easy Auth as code on production and test: require authentication everywhere except health
- Securing Kudu/SCM and other endpoints
- Automated gate reachability check

## Technical Approach

Bicep for the authentication settings; a reachability probe that expects a redirect to Microsoft sign-in for unauthenticated requests.

## Stories

---

### S-14.01.01: Obtain the app registration and user assignment

**Estimated Hours:** TBD

As a Program Architect, I want client IT to create the single-tenant registration and require user assignment so that only pilot users can pass the gate.

_Acceptance criteria:_

- [ ] A single-tenant app registration exists in the company tenant with the required consent.
- [ ] "User assignment required" is enabled and the pilot users (up to 50) or a group are assigned.
- [ ] Answers to the open questions are recorded and ADR-0021 is updated if refused.

_Notes:_ ADR-0021 decision items 4 and 5.

---

### S-14.01.02: Configure Easy Auth as code

**Estimated Hours:** TBD

As a Software Engineer, I want the gate defined in Bicep so that production and test are gated identically.

_Acceptance criteria:_

- [ ] Authentication is required for every path on both environments except a platform health path; multi-tenant sign-in is not permitted.
- [ ] The issuer is restricted to the company tenant.
- [ ] Any client secret is an App Service setting or Key Vault reference.

_Notes:_ SEC-01; NFR-009.

---

### S-14.01.03: Secure the other App Service endpoints

**Estimated Hours:** TBD

As a Software Engineer, I want the deployment console and other endpoints secured so that the gate cannot be bypassed.

_Acceptance criteria:_

- [ ] Kudu/SCM and other management endpoints are not reachable anonymously.
- [ ] Only the health path is anonymous on the application.
- [ ] The configuration is defined as code.

_Notes:_ ADR-0021 consequences.

---

### S-14.01.04: Add the automated gate reachability check

**Estimated Hours:** TBD

As a Software Engineer, I want an automated check that unauthenticated requests are redirected to sign-in so that a misconfiguration is caught.

_Acceptance criteria:_

- [ ] An unauthenticated request to any application path returns a redirect to Microsoft sign-in.
- [ ] The check runs against production and test and after every deployment.
- [ ] Leaving the test environment ungated is not possible without failing the check.

_Notes:_ SEC-12.
