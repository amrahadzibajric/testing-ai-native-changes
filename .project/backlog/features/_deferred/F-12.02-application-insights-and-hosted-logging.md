## Description

Wires hosted telemetry with sampling, keeps personal data out of it, and adds an availability probe for office hours.

## Scope Detail

- Application Insights and Log Analytics with sampling
- Log discipline: ids not emails, no request bodies or identity headers, short retention
- Uptime probe during office hours

## Technical Approach

Telemetry SDK configured in the web application; retention set in Bicep; a standard availability test.

## Stories

---

### S-12.02.01: Wire Application Insights with sampling

**Estimated Hours:** TBD

As a Software Engineer, I want hosted telemetry so that errors and admin actions can be investigated in the pilot.

_Acceptance criteria:_

- [ ] Errors, request telemetry and the admin action log lines reach Application Insights with sampling configured for the free-allowance budget.
- [ ] The instrumentation key or connection string is a setting, not code.
- [ ] Local logging continues to work unchanged.

_Notes:_ NFR-019.

---

### S-12.02.02: Enforce log discipline in hosted telemetry

**Estimated Hours:** TBD

As a Software Engineer, I want telemetry free of personal data so that hosting does not increase privacy exposure.

_Acceptance criteria:_

- [ ] Emails, names, request bodies and gate identity headers do not appear in telemetry; people are referenced by id.
- [ ] Retention is set to the agreed short period.
- [ ] A review of sampled telemetry confirms compliance.

_Notes:_ SEC-09.

---

### S-12.02.03: Add an office-hours availability probe

**Estimated Hours:** TBD

As a Software Engineer, I want an uptime probe so that outages during office hours are noticed.

_Acceptance criteria:_

- [ ] A probe checks the health path during 08:00 to 20:00 on working days and alerts on failure.
- [ ] The probe works with the access gate (health path excluded from authentication or a token is used).
- [ ] No formal SLA is implied; the target is best effort.

_Notes:_ NFR-007.
