## Description

Reads the sign-in name and immutable object identifier that the gate passes to the application and records them read-only on every audit event beside the picked person, with an informational mismatch indicator.

## Scope Detail

- Gate identity reader (audit metadata only, never authorisation)
- Population of gate fields on audit events
- Mismatch indicator by case-insensitive email comparison
- Admin visibility of mismatches

## Technical Approach

A small reader component reading platform headers; audit recorder extended to copy the values; a mismatch computed at write time.

## Stories

---

### S-14.02.01: Read the gate identity

**Estimated Hours:** TBD

As a Software Engineer, I want a reader for the gate identity headers so that the audit trail can name the authenticated account.

_Acceptance criteria:_

- [ ] The header names and formats are verified against current documentation and recorded.
- [ ] Missing headers (local runs, tests, system events) yield empty values without error.
- [ ] The values are never used to authorise anything.

_Notes:_ ADR-0021 decision item 3.

---

### S-14.02.02: Record the gate identity on audit events

**Estimated Hours:** TBD

As a Software Engineer, I want the gate fields filled on every audit event so that admin actions are attributable to a real account.

_Acceptance criteria:_

- [ ] Every person-initiated audit event stores the sign-in name and object id beside the picked person.
- [ ] `gate_identity_mismatch` is true when the gate account does not correspond to the picked person's email, ignoring case, and empty when no gate identity is present.
- [ ] The values are excluded from application logs and telemetry (SEC-09).

_Notes:_ SEC-05; audit.md.

---

### S-14.02.03: Show mismatches to admins

**Estimated Hours:** TBD

As a Software Engineer, I want mismatches visible to admins so that impersonation within the tenant can be reviewed.

_Acceptance criteria:_

- [ ] An admin can filter or view audit events flagged as mismatches.
- [ ] The indicator is informational and never blocks an action.
- [ ] The view states that a mismatch can be legitimate (for example a lent account) and is not proof of misuse.

_Notes:_ ADR-0021 decision item 3.
