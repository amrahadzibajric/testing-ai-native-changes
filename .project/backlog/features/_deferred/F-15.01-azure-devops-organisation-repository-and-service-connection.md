## Description

Sets up the Azure DevOps organisation and project, hosts the repository and creates the deployment service connection to the client's subscription.

## Scope Detail

- Decision on organisation and repository location; hosted parallelism
- Service connection with workload identity federation where allowed
- Branch policies

## Technical Approach

Administrative setup guided by client IT constraints; no application code.

## Stories

---

### S-15.01.01: Decide organisation and repository location

**Estimated Hours:** TBD

As a Program Architect, I want the organisation and repository location decided so that pipelines have a home.

_Acceptance criteria:_

- [ ] The location of the Azure DevOps organisation and source repository is decided by the project lead and recorded.
- [ ] Hosted-agent parallelism (free-tier grant or purchase) is confirmed.
- [ ] The repository is available to the team.

_Notes:_ ADR-0023 follow-ups.

---

### S-15.01.02: Create the service connection

**Estimated Hours:** TBD

As a Software Engineer, I want a service connection so that pipelines can deploy to the client subscription without a long-lived secret.

_Acceptance criteria:_

- [ ] Client IT grants deployment permission and a service connection exists, using workload identity federation where the tenant allows it.
- [ ] Scope is limited to the pilot resource groups.
- [ ] The connection is verified with a no-op deployment.

_Notes:_ ADR-0023 consequences.

---

### S-15.01.03: Apply branch policies

**Estimated Hours:** TBD

As a Software Engineer, I want branch protection so that only validated changes reach main.

_Acceptance criteria:_

- [ ] Pull requests require the validation pipeline to pass and at least one review.
- [ ] Direct pushes to main are blocked.
- [ ] Production pipeline changes require review.

_Notes:_ Security assessment deferred item (branch protection).
