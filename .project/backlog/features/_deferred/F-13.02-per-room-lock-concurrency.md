## Description

Implements the per-room row lock in the existing booking-write service and re-proves the no-double-booking guarantee against SQL Server.

## Scope Detail

- UPDLOCK on the room row inside the transaction, fixed order when an edit changes room
- Parallel-request tests on SQL Server via Testcontainers
- Decision note on the slot-table safeguard

## Technical Approach

Substitute the write service's locking strategy behind the provider-neutral seam created in F-06.02.

## Stories

---

### S-13.02.01: Implement the per-room lock

**Estimated Hours:** TBD

As a Software Engineer, I want a per-room row lock so that writes serialise per room on Azure SQL.

_Acceptance criteria:_

- [ ] Create, edit, remainder rebooking and import take the room lock before re-checking rules.
- [ ] An edit that changes room locks both rooms in a fixed order and cannot deadlock with another such edit.
- [ ] Callers of the write service need no change.
