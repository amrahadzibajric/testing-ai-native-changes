## Description

Repeats the tests whose outcome depends on the engine: collation, date and time handling, audit content, report purge and sweeper behaviour, and takes a first performance baseline on SQL Server.

## Scope Detail

- Case-insensitive uniqueness including accented characters
- Time handling around 25 October 2026 and 28 March 2027 with `datetime2`
- Audit, purge and sweeper transitions on SQL Server
- Baseline for NFR-003 and NFR-004 on the engine

## Technical Approach

Point the portable integration fixture at a SQL Server container and re-run the affected suites unchanged; add the accented-character cases.

## Stories

---

### S-13.03.01: Verify collation including accented characters

**Estimated Hours:** TBD

As a QA Engineer, I want duplicate detection verified on SQL Server so that NFR-023 holds for accented names.

_Acceptance criteria:_

- [ ] A person email or room name differing only in case or accents is refused as a duplicate according to the chosen collation.
- [ ] Import matching of room names and emails behaves the same.
- [ ] The result is recorded and any collation decision is added to the ADR.

_Notes:_ NFR-023; ADR-0025 rule 3.

---

### S-13.03.02: Verify time handling on SQL Server

**Estimated Hours:** TBD

As a QA Engineer, I want the daylight-saving and office-hours tests re-run so that datetime2 storage behaves like the POC.

_Acceptance criteria:_

- [ ] The DST tests around 25 October 2026 and 28 March 2027 pass on SQL Server.
- [ ] A guard confirms no `DateTimeOffset` reached the model.
- [ ] Weekday and office-hours tests pass in both offsets.

_Notes:_ NFR-015.

---

### S-13.03.03: Re-run lifecycle, audit and purge tests and take a baseline

**Estimated Hours:** TBD
