## Description

Verifies that pilot users can pass the gate from phones and laptops on any network and prepares the client-side message that this is tenant-level gating, not a new application login.

## Scope Detail

- Phone and laptop sign-in checks off the office network and on mobile data
- Conditional Access impact assessment and fallback
- Presenting the gate to Office Operations as gating, not a login feature; onboarding of new people into user assignment

## Technical Approach

Manual verification plan run on a small set of devices, results recorded against the acceptance criteria.

## Stories

---

### S-14.03.01: Verify phones and laptops off the office network

**Estimated Hours:** TBD

As a QA Engineer, I want to verify sign-in from real devices off the office network so that the no-VPN requirement is proven.

_Acceptance criteria:_

- [ ] An assigned user can reach and use the app from a phone on mobile data and a laptop at home without a VPN.
- [ ] A user who is not assigned, and a personal account outside the tenant, are refused at sign-in.
- [ ] Any Conditional Access block on personal phones is recorded with a proposed fallback.

_Notes:_ ADR-0021 context; NFR-009.

---

### S-14.03.02: Communicate the gate and define user onboarding

**Estimated Hours:** TBD

As a Program Architect, I want the gate explained to Office Operations and a process to add users so that adding a person is not forgotten.

_Acceptance criteria:_

- [ ] Office Operations has been told the gate is tenant-level gating and pick-a-user remains in the app.
- [ ] A short process states that adding a person in the app also requires assigning them to the enterprise application (when user assignment is required).
- [ ] The process is included in the go-live runbook (F-17.02).

_Notes:_ ADR-0021 negative consequence (presentation to Office Operations).
