## Description

Switches the application to real sign-in, retires or restricts the picker to a test-only environment, and verifies that the privacy and admin restrictions are now genuinely enforced.

## Scope Detail

- Configuration switch to the Entra implementation
- Picker removed or limited to test-only
- Verification with a stubbed OIDC provider and a developer tenant

## Technical Approach

Configuration-driven implementation selection; integration test with a stubbed provider and a manual test against a developer tenant.

## Stories

---

### S-16.02.01: Switch by configuration and retire the picker

**Estimated Hours:** TBD

As a Software Engineer, I want the Entra implementation selected by configuration and the picker retired so that pick-a-user cannot be used in production.

_Acceptance criteria:_

- [ ] Production configuration selects the Entra implementation; the picker page and Switch user control are absent.
- [ ] The picker remains available only in a test-only configuration.
- [ ] Anonymous requests are sent to sign-in.

_Notes:_ ADR-0022.

---

### S-16.02.02: Verify enforced privacy and admin restrictions

**Estimated Hours:** TBD

As a QA Engineer, I want the role and privacy behaviour verified under real sign-in so that the accepted pilot limitation is closed.

_Acceptance criteria:_

- [ ] An integration test with a stubbed OIDC provider and a manual test with a developer tenant confirm the sign-in flow.
- [ ] An employee cannot act as an admin or read another person's bookings by any UI route.
- [ ] The residual risk record for ADR-0005 is updated.

_Notes:_ Test strategy v1.2 (when the in-app sign-in phase starts).
