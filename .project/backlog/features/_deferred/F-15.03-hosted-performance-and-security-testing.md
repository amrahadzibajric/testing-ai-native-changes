## Description

Runs k6 performance thresholds and an OWASP ZAP baseline nightly against the deployed test environment outside working hours, and adds dependency and static analysis scanning to CI.

## Scope Detail

- Nightly k6 against NFR-003, NFR-004 and NFR-005 thresholds
- Nightly ZAP baseline
- Dependency and static analysis scanning in the pipeline

## Technical Approach

Nightly pipeline stage reusing the local k6 scripts and ZAP instructions from F-10.02, with results published as alerts.

## Stories

---

### S-15.03.01: Run nightly k6 thresholds on the hosted test environment

**Estimated Hours:** TBD

As a QA Engineer, I want nightly performance runs so that regressions against the NFRs are seen early.

_Acceptance criteria:_

- [ ] k6 runs nightly with thresholds for page response (p95 under 2 seconds), import of up to 500 rows under 1 minute and concurrent booking correctness.
- [ ] Runs happen outside working hours and results alert without blocking merges.
- [ ] Failing thresholds record the SQL tier as a suspect.

_Notes:_ NFR-003, NFR-004, NFR-005.

---

### S-15.03.02: Run a nightly ZAP baseline

**Estimated Hours:** TBD

As a QA Engineer, I want a nightly ZAP baseline so that web vulnerabilities are found on the deployed application.

_Acceptance criteria:_

- [ ] A ZAP baseline scan runs against the gated test environment using the pipeline token.
- [ ] Findings above the agreed severity raise an alert with a triage owner.
- [ ] The scan is read-only.

_Notes:_ Security assessment deferred item (baseline scan against deployed environment).

---

### S-15.03.03: Add dependency and static analysis scanning to CI

**Estimated Hours:** TBD

As a Software Engineer, I want scanning in CI so that the manual dependency check from the POC is automated.

_Acceptance criteria:_

- [ ] Vulnerable dependencies fail the PR validation stage.
- [ ] Static analysis runs in CI and its findings are visible on the pull request.
- [ ] The manual pre-demonstration command remains available.
