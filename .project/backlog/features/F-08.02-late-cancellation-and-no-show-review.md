## Description

Lets admins see who cancels late and who does not show up, with counts per person over a chosen period. It is informational only: nothing happens automatically as a result.

## Scope Detail

- Late-cancellation view with counts per person for a period
- No-show view with counts per person for a period
- Exclusion of admin-origin cancellations from late counts; edits never counted
- Review-only guarantee: no automatic blocking, limit reduction or notification
- Web and phone screens

## Technical Approach

Admin read models aggregating on the late flag, cancellation origin and no-show status with the review indexes; no write paths.

## Stories

---

### S-08.02.01: Show late cancellations with counts per person

**Estimated Hours:** TBD

As a Software Engineer, I want a late-cancellation view so that admins can see who cancels late and how often.

_Acceptance criteria:_

- [ ] The view lists bookings flagged as late cancellations with the person and times, and shows counts per person over a chosen period.
- [ ] Only bookings cancelled by their owner less than 2 hours before start appear.
- [ ] An admin sees Y's cancellation from E2E-007 in this view.

_Notes:_ AO-03; E2E-007 step 4.

---

### S-08.02.02: Show no-shows with counts per person

**Estimated Hours:** TBD

As a Software Engineer, I want a no-show view so that admins can see who reserves rooms and does not use them.

_Acceptance criteria:_

- [ ] The view lists No-show bookings (effective status) with the person and shows counts per person over a chosen period.
- [ ] The period selection applies to both review views consistently.
- [ ] Results include no-shows persisted by the sweeper and those still only effective.

_Notes:_ M-05 capability 4; E2E-009 step 2.

---

### S-08.02.03: Keep the reports honest

**Estimated Hours:** TBD

As a Software Engineer, I want the counting rules enforced so that reports reflect only the person's own behaviour.

_Acceptance criteria:_

- [ ] Cancellations from room or person deactivation, and admin cancellations of someone else's booking, are never counted as late cancellations.
- [ ] Edits are never counted or flagged, however close to the start.
- [ ] The late flag is never changed after cancellation.

_Notes:_ AO-04, AO-05; ADR-0015 decision 3.

---

### S-08.02.04: Build the review screens and guarantee review-only behaviour

**Estimated Hours:** TBD

As a Software Engineer, I want the review screens and a guarantee of no automatic consequences so that admins use them for judgement, not enforcement.

_Acceptance criteria:_

- [ ] The web and phone review screens follow S03-review and S03-review-mobile with the late-cancellation and no-show views and per-person counts.
- [ ] No code path blocks a person, reduces their limit, or sends any notification because of late cancellations or no-shows.
- [ ] Employees cannot open the review screens.

_Notes:_ AO-02; ADR-0009; LC-11.
