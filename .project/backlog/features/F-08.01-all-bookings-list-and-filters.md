## Description

Gives admins a table-first view of every booking with room, person, date, time, attendees and status, filterable by room, person and status, plus recommended date range and late-cancellation filters.

## Scope Detail

- Admin-only query over all bookings
- Filters: room, person, status (Confirmed, Checked in, Cancelled, Cancelled by admin, No-show, Done), date range, late cancellation
- Status mapping including the derived "Cancelled by admin"
- Web table with detail pane and phone list with a filter sheet

## Technical Approach

Admin read model with filter composition over the indexed booking table, paging suitable for a few thousand rows, effective status applied.

## Stories

---

### S-08.01.01: Query all bookings with filters

**Estimated Hours:** TBD

As a Software Engineer, I want an admin query over all bookings so that admins can find any booking by room, person and status.

_Acceptance criteria:_

- [ ] Filters by room, person, status, date range and late cancellation can be combined; results are ordered by date and time and paged.
- [ ] Each row shows room, person, date, time, attendees and status.
- [ ] The query is available only through the admin policy.

_Notes:_ AO-01; E2E-009 step 1; a few thousand bookings must page in under 2 seconds locally.

---

### S-08.01.02: Map statuses including "Cancelled by admin"

**Estimated Hours:** TBD

As a Software Engineer, I want the status filter to include the derived "Cancelled by admin" so that admins can find admin actions.

_Acceptance criteria:_

- [ ] The status filter offers Confirmed, Checked in, Cancelled, Cancelled by admin, No-show and Done.
- [ ] "Cancelled by admin" matches Cancelled bookings whose origin is not OwnerCancelled; "Cancelled" matches OwnerCancelled.
- [ ] Effective status is used, so a lagging sweeper does not hide a no-show.

_Notes:_ M-05 capability 2; data model status mapping.

---

### S-08.01.03: Build the web table with detail pane

**Estimated Hours:** TBD

As a Software Engineer, I want the table-first web screen so that admins can scan many bookings and inspect one.

_Acceptance criteria:_

- [ ] The screen follows S03-all-bookings: filter bar, table with the shared status pills, and a detail pane for the selected booking.
- [ ] Compact density is available for admin tables.
- [ ] Empty results show the empty state; the screen is keyboard operable.

_Notes:_ Design direction: admin views are table-first.
