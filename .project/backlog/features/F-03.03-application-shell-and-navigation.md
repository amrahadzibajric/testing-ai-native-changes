**Screen references:** Navigation artboard; S03-admin-mobile

## Description

Delivers the page layout with a slim top navbar on the web and a bottom tab bar on the phone, always showing who the presenter is acting as, their role and a Switch user control.

## Scope Detail

- Web navbar: Find a room, My bookings; admins add All bookings, Review, Rooms, People, Import; current user, role and Switch user at right
- Phone tab bar: Find, My bookings, and for admins Admin
- Admin hub list on the phone
- Role-aware rendering and anonymous redirect to the picker

## Technical Approach

A shared Razor layout reading `ICurrentUser`. Visibility of links is presentation only; the server enforces access in F-04.03.

## Stories

---

### S-03.03.01: Build the base layout and web navbar

**Estimated Hours:** TBD

As a Software Engineer, I want a base layout and slim navbar so that every page has consistent navigation and identity display.

_Acceptance criteria:_

- [ ] An employee sees Find a room and My bookings; an admin additionally sees All bookings, Review, Rooms, People and Import (Import hidden when disabled by configuration).
- [ ] The acting person's name, their role and a Switch user control appear at the right on every page.
- [ ] The active destination is marked and the navbar is keyboard operable.

_Notes:_ Design direction, Navigation.

---

### S-03.03.02: Build the phone tab bar

**Estimated Hours:** TBD

As a Software Engineer, I want a bottom tab bar on phone-size screens so that the main destinations are reachable by thumb.

_Acceptance criteria:_

- [ ] Find and My bookings tabs appear for everyone; an Admin tab appears for admins only.
- [ ] Every touch target is at least 44 px.
- [ ] The tab bar replaces the web navbar below the phone breakpoint.

_Notes:_ Design direction, Navigation (mobile).

---

### S-03.03.03: Build the phone admin hub

**Estimated Hours:** TBD

As a Software Engineer, I want an admin hub list on the phone so that an admin can reach All bookings, Review, Rooms, People and Import.

_Acceptance criteria:_

- [ ] The Admin tab opens a list of the admin destinations that are enabled.
- [ ] The list uses no stat cards or KPI tiles.
- [ ] Each entry opens the corresponding phone-size admin screen.

_Notes:_ S03-admin-mobile; design direction refusal of KPI rows.

---

### S-03.03.04: Render navigation by role and redirect anonymous requests

**Estimated Hours:** TBD

As a Software Engineer, I want the shell to render from the acting user and send a request with no picked user to the picker so that the app never shows a page without an identity.

_Acceptance criteria:_

- [ ] Navigation items are chosen from the acting person's role read through `ICurrentUser`.
- [ ] A request with no valid picked person is redirected to the pick-a-user page.
- [ ] Hiding a link never replaces server enforcement: typing an admin URL as an employee is refused (F-04.03).

_Notes:_ NFR-010.
