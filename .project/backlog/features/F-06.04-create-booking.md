## Description

Lets a user book a room by picking room, date, start, end and attendee head count. Admins can also book on behalf of another person and for themselves. Every refusal names the broken rule.

## Scope Detail

- Book for self through the write service
- Admin booking on behalf of an active person, counting toward that person's limit
- Admin booking for self with no limit but all other rules
- Web book drawer prefilled from the selected slot; phone booking flow
- Refusal states: limit reached, conflict, rule failures

## Technical Approach

Razor Pages handlers calling the booking-write service; person picker restricted to active people for admins; UI built from F-03 components.

## Stories

---

### S-06.04.01: Book a room for myself

**Estimated Hours:** TBD

As a Software Engineer, I want the create-booking action so that an employee can reserve a free room in one interaction.

_Acceptance criteria:_

- [ ] Given a free slot within all rules, the employee's booking is created as Confirmed with room, date, start, end and attendees, and appears in My bookings.
- [ ] The room shows busy for everyone for that period and the employee's upcoming count rises by 1.
- [ ] BookingCreated is audited and the success is confirmed on screen.

_Notes:_ E2E-001 step 4; attendees are a head count only.

---

### S-06.04.02: Book on behalf of another person (admin)

**Estimated Hours:** TBD

As a Software Engineer, I want an admin to book for another active person so that admins can help colleagues.

_Acceptance criteria:_

- [ ] An admin can select an active person; the booking's owner is that person and its creator is the admin.
- [ ] The booking counts toward that person's 3-booking limit; a booking that would exceed it is refused with the named rule.
- [ ] Inactive people cannot be selected.

_Notes:_ BR-09; E2E-004 steps 1 and 2.

---

### S-06.04.03: Admin books for themselves without a limit

**Estimated Hours:** TBD

As a Software Engineer, I want an admin's own bookings to be exempt from the 3-booking limit while every other rule still applies so that admins can work without artificial limits.

_Acceptance criteria:_

- [ ] An admin can hold more than 3 upcoming bookings for themselves.
- [ ] A 5-hour booking, an off-grid booking or an overlapping booking by an admin is still refused.
- [ ] The exemption does not apply when the admin books for another person.

_Notes:_ BR-10, BR-11; E2E-004 steps 3 and 4.

---

### S-06.04.04: Build the book drawer for the web

**Estimated Hours:** TBD

As a Software Engineer, I want the book drawer so that a user can confirm a selected slot with a clear view of the rules.

_Acceptance criteria:_

- [ ] The drawer opens from a selected slot with room, date, start and end prefilled and asks for attendees; admins also see the person picker.
- [ ] A refusal (limit reached, room already booked, capacity, duration, hours, grid, past) is shown inline naming the rule and leaves the drawer open with input kept.
- [ ] The primary action uses the accent; the drawer is keyboard operable and focus returns to the board on close.

_Notes:_ S02-book-drawer; S02-states.

---

### S-06.04.05: Build the phone booking flow

**Estimated Hours:** TBD

As a Software Engineer, I want a phone-friendly booking flow so that a booking can be made from a phone in under a minute.

_Acceptance criteria:_

- [ ] From a free slot in the phone list the user reaches a booking form or sheet with the same fields, validation and named refusals as the web.
- [ ] On success the user sees a confirmation and can go to My bookings.
- [ ] The prototype flow (pick Lena, book Board 10:45, confirmation, My bookings) works end to end on web and phone widths.

_Notes:_ 04 Prototype; NFR-016.
