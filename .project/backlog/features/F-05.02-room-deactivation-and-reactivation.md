**Feature ID:** F-05.02
**EPIC:** [E-05: Room Management](../epics/E-05-room-management.md)

**Phase:** Phase 1 — POC
**Sprint Range:** TBD (Phase 10)

**Surfaces:** Web (admin), Phone browser (admin)

**ADR References:** ADR-0014 (pattern), ADR-0015 (decision 3)

**Screen references:** S03-rooms, S03-rooms-mobile, S03-states (deactivation confirm)

## Description

Lets an admin take a room out of use with a warning of the consequence, cancels future bookings as cancelled by admin, hides the room from booking and import, and lets it be reactivated later.

## Scope Detail

- Deactivation preview with count, confirmation and cascade
- Inactive room excluded from availability, booking targets, edit targets and import
- Reactivation without restoring bookings
- Confirmation UI on web and phone

## Technical Approach

Room service calls the shared cascade service (F-07.05) in one transaction with the room state change and the audit events.

## Stories

---

### S-05.02.01: Deactivate a room with a warning and cascade

**Estimated Hours:** TBD

As a Software Engineer, I want deactivation to show how many bookings will be cancelled and then cancel them so that admins understand the consequence and bookers are told it was an admin action.

_Acceptance criteria:_

- [ ] The admin sees the count of future Confirmed bookings before confirming.
- [ ] On confirm the room becomes inactive and its future Confirmed bookings are cancelled with origin RoomDeactivated, not late-flagged; in-progress, checked-in and past bookings are untouched.
- [ ] Booking cancellations and the room change succeed or fail together, and RoomDeactivated is audited.

_Notes:_ RM-03, RM-04, RM-07; E2E-010 steps 1 to 4.

---

### S-05.02.02: Exclude inactive rooms from booking, edit and import

**Estimated Hours:** TBD

As a Software Engineer, I want inactive rooms excluded everywhere new bookings are made so that nobody can book a room that is out of use.

_Acceptance criteria:_

- [ ] An inactive room does not appear in availability or the book form and is refused as an edit target.
- [ ] An import row naming an inactive room (for example Old Room) is rejected with the reason RoomInactive.
- [ ] Booking history for the room remains visible to admins and filterable.

_Notes:_ BR-13; IM-02.

---

### S-05.02.03: Reactivate a room

**Estimated Hours:** TBD

As a Software Engineer, I want to reactivate a room so that it can be booked again after renovation.

_Acceptance criteria:_

- [ ] An admin can reactivate an inactive room, which then appears in availability.
- [ ] Bookings cancelled at deactivation are not restored.
- [ ] RoomReactivated is audited.

_Notes:_ RM-06; E2E-010 step 5.

---

### S-05.02.04: Build the deactivation and reactivation interactions

**Estimated Hours:** TBD

As a Software Engineer, I want clear confirm interactions on web and phone so that a room is never deactivated by accident.

_Acceptance criteria:_

- [ ] Deactivation uses the confirm modal (web) or sheet (phone) that states the number of bookings to be cancelled and names the destructive action.
- [ ] A deactivated room is visibly marked in the room list and offers Reactivate.
- [ ] A room with no future bookings shows a zero count and the same confirmation.

_Notes:_ Well-meaning admin risk in the security assessment (accidental mass cancellation).
