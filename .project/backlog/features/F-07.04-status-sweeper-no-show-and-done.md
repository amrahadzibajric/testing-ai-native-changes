## Description

Runs an in-process background service every ~30 seconds that marks unattended bookings as No-show and completed bookings as Done, and provides the shared effective-status computation so all rules are correct even between runs or after a restart.

## Scope Detail

- Hosted service about every 30 seconds with idempotent, set-based updates and status guards
- Effective status: Confirmed past start plus 15 minutes reads No-show; Checked in past end reads Done
- Catch-up after restart; repeat-safe; resilient to exceptions
- Audit events by the System actor

## Technical Approach

`BackgroundService` calling the lifecycle service; SQL updates guarded by status and time thresholds; one shared effective-status function used by availability, overlap, check-in and listings.

## Stories

---

### S-07.04.01: Run the no-show and done transitions

**Estimated Hours:** TBD

As a Software Engineer, I want a background service that applies the automatic transitions so that unused rooms are released and finished meetings are closed without manual work.

_Acceptance criteria:_

- [ ] A Confirmed booking whose start plus 15 minutes has passed becomes No-show with the no-show moment recorded, and the remaining time becomes bookable.
- [ ] A Checked in booking whose end has passed becomes Done.
- [ ] A Confirmed booking that starts and is never checked in never becomes Done; a checked-in booking not ended manually becomes Done at its end.

_Notes:_ LC-08, LC-10; E2E-005 step 3, E2E-006 step 1.

---

### S-07.04.02: Provide the shared effective-status computation

**Estimated Hours:** TBD

As a Software Engineer, I want one effective-status function so that availability, overlap, check-in and listings are correct even if the sweeper is late.

_Acceptance criteria:_

- [ ] Effective status treats a Confirmed booking past start plus 15 minutes as No-show and a Checked in booking past end as Done, whether or not the sweeper has persisted the change.
- [ ] Availability, overlap, check-in, My bookings and oversight lists all use this one function.
- [ ] The no-show moment used equals start plus 15 minutes, consistently with the check-in window.

_Notes:_ ADR-0018 read-time safety net; NFR-006; data-model "Effective status".

---

### S-07.04.03: Make the service resilient and repeat-safe

**Estimated Hours:** TBD

As a Software Engineer, I want the service to be idempotent and resilient so that restarts, repeats and errors cannot corrupt state.

_Acceptance criteria:_

- [ ] Updates carry a status guard so running twice, or two runs overlapping, changes nothing extra.
- [ ] After the POC has been stopped and restarted, the first run catches up on missed transitions.
- [ ] An exception in one run is logged and the next run proceeds; the service never crashes the host.

_Notes:_ Risk 7 in arch v1.2 (sweeper not running when POC stopped).

---

### S-07.04.04: Meet the timing target and audit as the system

**Estimated Hours:** TBD

As a Software Engineer, I want transitions within one minute and audited as system actions so that the automatic behaviour is timely and traceable.

_Acceptance criteria:_

- [ ] Status changes occur within one sweeper interval and within 1 minute of the trigger moment under normal load, including while an import is running.
- [ ] BookingMarkedNoShow and BookingMarkedDone are audited with actor kind System.
- [ ] Sweeper transactions are short and use the busy timeout so they do not starve or block booking writes.

_Notes:_ NFR-006; NFR-020.
