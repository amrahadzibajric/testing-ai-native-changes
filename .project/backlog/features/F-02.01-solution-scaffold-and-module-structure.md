## Description

Creates the ASP.NET Core Razor Pages modular monolith with internal modules mirroring M-01 to M-06, plus configuration, logging and automated enforcement of the module and seam rules. It is the container into which every later feature is built.

## Scope Detail

- Solution, web project, internal modules and test project skeletons
- Validated configuration for zone, bootstrap admin, seed toggle and import switches and caps
- Local console and file logging that avoids personal data
- Automated enforcement of module boundaries and seam usage

## Technical Approach

Single deployable ASP.NET Core application with modules as folders or class libraries as fixed in the baseline note. Options classes validated at startup. Structured logging to console and a rolling local file.

## Stories

---

### S-02.01.01: Create the solution and module skeleton

**Estimated Hours:** TBD

As a Software Engineer, I want a solution with a Razor Pages web project, one internal module per M-01 to M-06 and test project skeletons so that all features have an agreed home.

_Acceptance criteria:_

- [ ] `dotnet build` succeeds and `dotnet run` from the web project starts an empty application on localhost.
- [ ] Modules for Room Booking and Availability, Booking Lifecycle, Room Management, People and Identity, Admin Oversight and Booking Import exist with the dependency direction from the baseline note.
- [ ] Integration/API and E2E test project skeletons exist (contents come from E-10).

_Notes:_ Follows arch v1.2 Component view and S-01.01.04.

---

### S-02.01.02: Add validated application configuration

**Estimated Hours:** TBD

As a Software Engineer, I want strongly typed, validated configuration so that misconfiguration fails at startup with a clear message.

_Acceptance criteria:_

- [ ] Settings exist for OfficeTimeZone (default Europe/Berlin), BootstrapAdmin (name, email), Seed (demo data on or off), Import (enabled, file size cap, row cap) and the database file location.
- [ ] An invalid or unknown time zone, or an invalid import cap, stops startup with a message naming the setting.
- [ ] No setting exists that moves the clock or bypasses a rule.

_Notes:_ The clock rule supports SEC-11 (see F-02.03). Default caps proposed by the integration assessment: 1 MB and 2,000 rows.

---

### S-02.01.03: Add local logging that avoids personal data

**Estimated Hours:** TBD

As a Software Engineer, I want structured console and file logs that avoid emails and request bodies so that troubleshooting is possible without personal data in logs.

_Acceptance criteria:_

- [ ] Errors, admin actions (room and person changes, cancellations by admin, deactivations) and import runs are logged with person ids, not email addresses.
- [ ] Request bodies and uploaded file content are never logged.
- [ ] Logs are written to the console and a local rolling file and retained until the next reset.

_Notes:_ NFR-019; SEC-09 log discipline is cheap and built now. Application Insights is post-POC (E-12).

---

### S-02.01.04: Enforce module and seam boundaries automatically

**Estimated Hours:** TBD

As a Software Engineer, I want automated rules that stop modules from reaching around their seams so that the identity, clock and write-path guarantees cannot erode.

_Acceptance criteria:_

- [ ] The build fails if a module reads identity anywhere except through `ICurrentUser`.
- [ ] The build fails if code reads the system clock directly instead of the office clock.
- [ ] The build fails if a booking is created or moved anywhere except through the booking-write service.

_Notes:_ ADR-0022 follow-up (architecture test); ADR-0019; ADR-0020. The third rule becomes enforceable once F-06.02 exists.
