## Description

Provides bulk data generators, optional performance and security scan scripts and a dependency vulnerability check so that the POC's applicable NFRs can be measured and the demonstration build is checked.

## Scope Detail

- Bulk generators: 50 people, four rooms, about 5,000 bookings; import files of 300 and 500 rows
- Optional k6 smoke script with p95 under 2 seconds; optional OWASP ZAP baseline instructions
- Dependency vulnerability check wrapper

## Technical Approach

Scripts and small generator programs in a tools folder; no cloud services.

## Stories

---

### S-10.02.01: Generate bulk data and import volume files

**Estimated Hours:** TBD

As a QA Engineer, I want bulk data generators so that scale and import timing can be measured locally.

_Acceptance criteria:_

- [ ] A generator seeds 50 people, the four rooms and about 5,000 bookings across past and future dates into a scratch database.
- [ ] A generator produces valid import files of 300 and 500 rows relative to a go-live date.
- [ ] All generated data is fictional and the generators never touch the demonstration database.

_Notes:_ NFR-001, NFR-002, NFR-004; test strategy v1.2, Test Data Strategy (Performance).

---

### S-10.02.02: Provide optional performance and scan scripts

**Estimated Hours:** TBD

As a QA Engineer, I want an optional k6 smoke script and ZAP instructions so that a quick performance and security check can be run against the local app.

_Acceptance criteria:_

- [ ] A k6 script exercises availability search and booking with a p95 threshold of 2 seconds and is documented as indicative only.
- [ ] Instructions describe an optional OWASP ZAP baseline against the local app.
- [ ] Neither tool is required to close any POC acceptance criterion.

_Notes:_ NFR-003; test strategy v1.2, k6 and ZAP.

---

### S-10.02.03: Provide the dependency vulnerability check

**Estimated Hours:** TBD

As a Software Engineer, I want a single command that reports vulnerable dependencies so that each demonstration build is checked.

_Acceptance criteria:_

- [ ] A script runs `dotnet list package --vulnerable` including transitive packages and fails with a clear message if any is reported.
- [ ] The script is part of the documented pre-demonstration running order.
- [ ] Results are printed to the console and saved locally.

_Notes:_ Security assessment v1.2, deferred static analysis and dependency scanning until CI exists.
