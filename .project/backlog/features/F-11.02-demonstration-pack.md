## Description

Prepares the presenter: a demonstration script mapped to the E2E scenarios, a pre-demonstration checklist and the statement of what the POC is and is not, together with the confirmations to obtain from Office Operations.

## Scope Detail

- Demonstration script for E2E-001 to E2E-014 with the seeded data and timing notes
- Pre-demonstration checklist and running order
- POC statement and client confirmation list

## Technical Approach

Documents produced by the delivery team from the E2E scenarios, seed design and the confirmation pack (S-01.02.01).

## Stories

---

### S-11.02.01: Write the demonstration script

**Estimated Hours:** TBD

As a Program Architect, I want a script that maps the seeded data to the business scenarios so that the presenter can show every module without waiting or improvising.

_Acceptance criteria:_

- [ ] The script has a step list for E2E-001 to E2E-014 naming the person to pick, the screen and the expected result, using the seeded sample bookings.
- [ ] Time-driven scenarios (check-in, no-show, late cancellation) state which seeded booking to use and what to say if the start time has passed; there is no clock control.
- [ ] The import scenario uses the sample CSV and shows the rejected-rows report and re-import.

_Notes:_ ADR-0024 decision 5; e2e-scenarios.md.

---

### S-11.02.02: Write the pre-demonstration checklist

**Estimated Hours:** TBD

As a Program Architect, I want a checklist so that a demonstration build is only cut from a verified state.

_Acceptance criteria:_

- [ ] The checklist requires a green local run in the documented order: build, unit tests, integration and API tests, dependency check, E2E.
- [ ] It includes reset and seed, verifying the bootstrap admin settings, confirming the app listens on localhost only, and a note about the next daylight-saving transitions.
- [ ] It records that the sample CSV was regenerated for the intended go-live date.

_Notes:_ Test strategy v1.2, Running order (no pipeline); security assessment risk 5 and 7.

---

### S-11.02.03: State what the POC is and list the confirmations needed

**Estimated Hours:** TBD

As a Program Architect, I want a plain statement of the POC's nature and a list of confirmations so that the client's expectations are right and decisions are captured.

_Acceptance criteria:_

- [ ] The statement says it is a local proof of concept on synthetic data with no sign-in and no hosting, and that all functional scope is present.
- [ ] The confirmation list covers ADR-0011 (format), ADR-0012 (clean-up ownership), ADR-0013 (30-minute remainder), and the ADR-0014 and ADR-0015 rules, with a place to record answers.
- [ ] It includes the open questions to ask: IANA zone, whether Office Operations can supply an anonymised export, and the post-POC trigger and owner.

_Notes:_ Links to S-01.02.01 outcome log.
