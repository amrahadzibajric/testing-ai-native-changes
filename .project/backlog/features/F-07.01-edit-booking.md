## Description

Lets the owner (or an admin) change room, date, start, end and attendees of a Confirmed booking that has not started. The edit is validated as if it were a new request, excluding its own current slot, and is never treated as a new booking or a late change.

## Scope Detail

- Edit service using the write service with the booking's own slot excluded from overlap
- Refusal when the booking has started, finished or is not Confirmed
- Original booking unchanged on any failure
- Edit drawer (web) and edit sheet (phone)
- Audit with before and after values

## Technical Approach

Lifecycle service method calling the booking-write service; concurrency token from F-06.02; UI reuses the book drawer and sheet with prefilled values.

## Stories

---

### S-07.01.01: Edit a Confirmed booking that has not started

**Estimated Hours:** TBD

As a Software Engineer, I want an edit action so that an owner can change their plans without cancelling and rebooking.

_Acceptance criteria:_

- [ ] The owner or an admin can change room, date, start, end and attendees of a Confirmed booking that has not started; every M-01 rule is re-run with the booking's own slot excluded from the overlap check.
- [ ] The edit does not increase the person's upcoming count and is never flagged as a late cancellation, even seconds before start.
- [ ] An employee cannot edit another person's booking.

_Notes:_ LC-01 to LC-04; ADR-0007; E2E-003 step 2, E2E-007 step 3.

---

### S-07.01.02: Refuse invalid edits and leave the booking unchanged

**Estimated Hours:** TBD

As a Software Engineer, I want invalid edits refused with the named rule so that a failed edit never corrupts a booking.

_Acceptance criteria:_

- [ ] Editing a booking that has started, is checked in, done, no-show or cancelled is refused with a message that it has started or is no longer editable.
- [ ] An edit causing overlap, an off-grid time or an over-capacity head count is refused and the original booking is unchanged.
- [ ] If a room's capacity was lowered below the booking's attendees, any edit is refused until attendees are reduced.

_Notes:_ E2E-008, E2E-011 step 3, ADR-0014 rule 1.

---

### S-07.01.03: Build the edit interactions for web and phone

**Estimated Hours:** TBD

As a Software Engineer, I want the edit drawer and phone sheet so that users can change a booking with the same clarity as booking.

_Acceptance criteria:_

- [ ] The web drawer and the phone sheet open prefilled with the booking's current values and show refusals inline naming the rule.
- [ ] The Edit action appears only for bookings the lifecycle rules allow.
- [ ] Success shows a confirmation and returns to My bookings with the updated booking.

_Notes:_ S02-edit-sheet-mobile.

---

### S-07.01.04: Audit edits with before and after values

**Estimated Hours:** TBD

As a Software Engineer, I want edits audited so that the trail shows what changed and who changed it.

_Acceptance criteria:_

- [ ] BookingEdited records the acting person, whether an admin acted, and the old and new start, end, room and attendees.
- [ ] Audit details use ids, not emails.
- [ ] The audit event is written in the same transaction as the edit.

_Notes:_ NFR-020; SEC-09.
