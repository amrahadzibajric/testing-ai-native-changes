## Description

Binds the application to loopback only and applies the local security baseline that still matters when the app is reachable only from the machine it runs on: forgery protection, safe cookie attributes, request limits and a locally stored key ring.

## Scope Detail

- Loopback-only binding with a startup refusal of non-loopback URLs
- Anti-forgery on all state-changing requests; POST-only state changes; safe cookie attributes
- Request body and upload limits
- Data protection key ring on the local file system

## Technical Approach

Kestrel endpoint configuration constrained to loopback; ASP.NET Core anti-forgery and cookie policy; request size limits; file-based key ring.

## Stories

---

### S-02.07.01: Bind to localhost only

**Estimated Hours:** TBD

As a Software Engineer, I want Kestrel bound to loopback only so that the unauthenticated pick-a-user application is never reachable from another machine.

_Acceptance criteria:_

- [ ] The application listens on localhost (127.0.0.1 and ::1) only.
- [ ] A configuration or command-line attempt to bind `0.0.0.0` or a machine IP stops startup with a message stating that the POC must run on localhost only.
- [ ] From another machine or a LAN address the application is not reachable.

_Notes:_ SEC-13; NFR-009 is met by not exposing. The run instructions forbid tunnels (F-11.01).

---

### S-02.07.02: Protect state changes against request forgery

**Estimated Hours:** TBD

As a Software Engineer, I want anti-forgery tokens and POST-only state changes so that another page in the browser cannot trigger cancel, deactivate or import.

_Acceptance criteria:_

- [ ] Every state-changing handler requires a valid anti-forgery token and is reachable only by POST.
- [ ] A state-changing request without a valid token is refused and changes nothing.
- [ ] The picker cookie is HttpOnly and SameSite; the Secure attribute is applied whenever HTTPS is used.

_Notes:_ SEC-03; SEC-02 attributes.

---

### S-02.07.03: Limit request and upload size

**Estimated Hours:** TBD

As a Software Engineer, I want request and upload size limits so that a large or malformed request cannot exhaust the process.

_Acceptance criteria:_

- [ ] Maximum request body and upload size are configured and enforced; an oversized request is refused with a clear message.
- [ ] The import file size and row caps come from configuration (S-02.01.02) and are enforced in F-09.01.
- [ ] Rate limiting on searches is optional locally and, if added, is configurable.

_Notes:_ SEC-08; NFR-004.

---

### S-02.07.04: Store the data protection key ring locally

**Estimated Hours:** TBD

As a Software Engineer, I want the data protection key ring stored on the local file system so that restarts do not invalidate the picker cookie.

_Acceptance criteria:_

- [ ] Restarting the application keeps an existing picker cookie valid.
- [ ] Deleting the key ring invalidates old cookies and sends users to the picker.
- [ ] The key ring location is configuration and not part of the domain model.

_Notes:_ ADR-0025 rule 9. Post-POC the key ring moves to the database or Key Vault (F-12.01).
