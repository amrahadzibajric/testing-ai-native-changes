## Description

Provides the single office clock and the office-zone conversions used by every rule: office hours, weekday, grid, the late rule, the check-in window and the import window. Instants are stored in UTC and evaluated in office local time, so daylight saving is handled in one place.

## Scope Detail

- Injectable clock over `TimeProvider`; the only source of "now"
- UTC to office local conversions and wall-clock helpers
- Refusal of nonexistent or ambiguous local times
- Guarantee that no clock control exists in the running application
- Office-local display helper for all pages

## Technical Approach

A thin office clock service wraps `TimeProvider` and the configured `TimeZoneInfo`. Test hosts substitute `FakeTimeProvider`; the production host registers only the system clock.

## Stories

---

### S-02.03.01: Provide the injectable office clock

**Estimated Hours:** TBD

As a Software Engineer, I want one office clock over `TimeProvider` so that all code reads "now" from a single injectable source.

_Acceptance criteria:_

- [ ] Production registers the system clock; no other code reads the system clock.
- [ ] The clock exposes the current instant in UTC and in office local time.
- [ ] A test host can replace the clock with a fake clock without changing application code.

_Notes:_ Enforced by S-02.01.04.

---

### S-02.03.02: Provide office-zone conversions and wall-clock helpers

**Estimated Hours:** TBD

As a Software Engineer, I want conversion and wall-clock helpers so that office hours, weekdays, the grid and the import window are evaluated in office local time across daylight saving changes.

_Acceptance criteria:_

- [ ] Helpers convert UTC to local and local to UTC, and return the local date, weekday, start of day, the 08:00 to 20:00 window and whether a time lies on the 15-minute grid.
- [ ] A local time that does not exist or is ambiguous is refused with a clear message.
- [ ] Weekday tests, start-of-day and displayed times are correct on both sides of Sunday 25 October 2026 and Sunday 28 March 2027.
- [ ] Changing the configured zone identifier requires no data migration.

_Notes:_ Elapsed-time rules (2-hour late rule, check-in window) are computed on instants, not local wall time.

---

### S-02.03.03: Guarantee that no clock control exists in the running application

**Estimated Hours:** TBD

As a Software Engineer, I want the fake clock registered only in test hosts so that no endpoint, setting, query parameter or UI can move time in the running application.

_Acceptance criteria:_

- [ ] Enumerating the application's routes and configuration shows no clock or time-override control.
- [ ] The fake clock type is not registered as a controllable service in the production host.
- [ ] An automated check asserts the absence of such an endpoint (SEC-11).

_Notes:_ ADR-0024 decision 5 (production-ready quality, no demo-only features).

---

### S-02.03.04: Display all times in office local time

**Estimated Hours:** TBD

As a Software Engineer, I want one display helper for times so that every screen shows office local time in a consistent format.

_Acceptance criteria:_

- [ ] Every page shows times in office local time in 24-hour `HH:mm` with tabular figures.
- [ ] No time zone selector exists anywhere.
- [ ] A booking displayed the day before and the day after a daylight-saving change shows the same wall-clock time.

_Notes:_ NFR-015; design direction (tabular figures wherever a time appears).
