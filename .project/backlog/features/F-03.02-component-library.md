## Description

Builds the reusable components from the Style Guide: booking status vocabulary, form controls including 15-minute time selectors, surfaces (table, detail pane, drawer, phone sheet, confirm modal) and feedback patterns that show the named broken rule.

## Scope Detail

- Status pills: Confirmed, Checked in, No-show, Cancelled, Late cancellation flag, "Cancelled by admin" label
- Controls: text, number, select, date, 15-minute time selectors, person picker, buttons, inline validation
- Surfaces: table (comfortable and compact), detail pane, drawer, phone bottom sheet, confirm modal
- Feedback: toast, inline refusal banner, live-region announcements

## Technical Approach

Razor partials or tag helpers with CSS from F-03.01 and a small amount of JavaScript for drawer, sheet and modal focus handling.

## Stories

---

### S-03.02.01: Build the booking status vocabulary

**Estimated Hours:** TBD

As a Software Engineer, I want one status component so that a booking looks the same on every screen and the status is never conveyed by colour alone.

_Acceptance criteria:_

- [ ] Confirmed shows a graphite outline, Checked in green, No-show amber, Cancelled grey with strikethrough, Late cancellation an amber flag.
- [ ] "Cancelled by admin" is a label derived from the cancellation origin on a Cancelled booking, never a separate status value.
- [ ] Every status also carries a text label so meaning does not depend on colour.

_Notes:_ Design direction (semantic colours); data model (no "Cancelled by admin" status).

---

### S-03.02.02: Build the form controls

**Estimated Hours:** TBD

As a Software Engineer, I want form controls with inline validation so that users see which rule they broke.

_Acceptance criteria:_

- [ ] Text, number, select, date, person picker and buttons exist; the primary action uses the accent and secondary actions do not.
- [ ] Time selectors offer only 15-minute marks.
- [ ] A validation or refusal message renders next to the control and names the broken rule (for example "Maximum booking length is 4 hours").

_Notes:_ NFR-017.

---

### S-03.02.03: Build the surfaces

**Estimated Hours:** TBD

As a Software Engineer, I want table, detail pane, drawer, phone sheet and confirm modal components so that admin and booking screens share layout patterns.

_Acceptance criteria:_

- [ ] The table supports comfortable and compact density and a detail pane.
- [ ] The drawer (web) and bottom sheet (phone) open and close with the defined motion, trap and restore focus, and close on Escape or a close control.
- [ ] The confirm modal shows a title, a consequence line and a confirm and cancel action, with the destructive confirm clearly worded.

_Notes:_ Used by book drawer, edit sheet, deactivation confirmations and the import screen.

---

### S-03.02.04: Build feedback patterns

**Estimated Hours:** TBD

As a Software Engineer, I want toast and inline banner components so that success and refusal feedback is consistent and announced to assistive technology.

_Acceptance criteria:_

- [ ] A success toast appears after a completed action and disappears without blocking.
- [ ] A refusal banner stays until dismissed or corrected and shows the named rule.
- [ ] Both are announced through a live region.

_Notes:_ NFR-017, NFR-018.
