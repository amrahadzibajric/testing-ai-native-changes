## Description

Lets a user choose a date, time range and optional minimum group size and see which active rooms are free, presented as the day timeline board on the web and a per-room list with next free slot on the phone. It never reveals who booked a busy slot.

## Scope Detail

- Availability query by date, time range and minimum capacity for active rooms
- Availability read model without any personal field
- Web timeline board: rooms as rows, 08:00 to 20:00 snapped to 15 minutes, live now line, capacity dimming, click or drag to start booking
- Phone per-room vertical list with next free slot

## Technical Approach

Server-rendered Razor Pages with a small JavaScript module for the board; an indexed availability query over effective status; a read model type with no owner data.

## Stories

---

### S-06.03.01: Implement the availability query

**Estimated Hours:** TBD

As a Software Engineer, I want an availability query so that a user sees which active rooms are free for a chosen date, time range and group size.

_Acceptance criteria:_

- [ ] For a date and time range the result lists every active room as free or busy for that range; inactive rooms never appear.
- [ ] Rooms whose capacity is below the requested number of people are flagged as too small (dimmed by the UI, not hidden).
- [ ] The result uses effective status and no-show occupancy, and typical responses stay under 2 seconds locally with 5,000 bookings.

_Notes:_ NFR-003; BR-06, BR-13; E2E-001 step 3.

---

### S-06.03.02: Keep the booker out of availability

**Estimated Hours:** TBD

As a Software Engineer, I want availability results without any booker information so that employees never see what others booked.

_Acceptance criteria:_

- [ ] The availability response and page contain no owner, creator or other personal data for any busy slot.
- [ ] The read model type has no personal fields, so a future change cannot add them by accident.
- [ ] As an admin the same page also shows only busy or free (admins see details in E-08, not here).

_Notes:_ NFR-012; SEC-04; E2E-001, E2E-014.

---

### S-06.03.03: Build the web timeline board

**Estimated Hours:** TBD

As a Software Engineer, I want the day timeline board so that a user answers "which room is free, when?" in one glance.

_Acceptance criteria:_

- [ ] Rooms are rows and 08:00 to 20:00 columns snapped to 15 minutes; bookings are blocks with no names; a single live "now" line shows the current time.
- [ ] Clicking or dragging free track selects a start and end and opens the book drawer (F-06.04); the selected slot uses the accent colour.
- [ ] The capacity filter dims rooms that are too small; the board is operable by keyboard.

_Notes:_ S02-find-room; design direction structural idea; no room-card grid.

---

### S-06.03.04: Build the phone per-room list

**Estimated Hours:** TBD

As a Software Engineer, I want a per-room vertical time list with a next-free-slot line so that phone users can find a room without a wide board.

_Acceptance criteria:_

- [ ] Each room shows its day as a vertical time list and a "next free slot" summary; touch targets are at least 44 px.
- [ ] Selecting a free slot opens the phone booking flow (F-06.04).
- [ ] The capacity filter and date selection work at phone width in Chrome and Safari.

_Notes:_ S02-find-room-mobile; NFR-016.
